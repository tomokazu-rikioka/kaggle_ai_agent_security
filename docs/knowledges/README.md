### 次に何をすべきか

1. **public**: champion（exp028 / exp073）を cap 0.99–0.993 で回して best-of の上端を拾う。
   これ以上の伸びは公開情報の範囲では見つかっていない。
2. **private（本命）**: multi-send DEPUTY の密度が黒字化するかは**未検証**で、
   一次実験の価値が最も高い（→ [06-private汎化](06-private汎化.md) 6-4）。
3. **最終提出**: EXFIL アーム（public 質量）＋ DEPUTY アーム（private ヘッジ）の
   ポートフォリオを 1 本持って shake-up に備える。

## アイデアを思いついたら

実験を回す前に **[04-レバー台帳](04-レバー台帳.md) 4-4 の事前判定ルーブリック**で赤／緑を確認する。
特に次は**確認済みの退行**なので、繰り返さない:

- champion の単一レバーを触るだけ（テンプレ数・文面長・`PROBE_REPS`・framing・アーム数）
- 短形化・出力抑制・「応答するな」系（発火率が落ちる）
- 密度 multi-post / continuation / stacking（リプレイコストが raw 増を相殺する）
- reasoning-effort への user 注入（構造的に不可能）
- リプレイ壁が予算より広いことへの賭け（VOID）
