## 8-2. ラウンド史

### Round 1（〜2026-07-18, exp001–010）— 静的ベースライン → fill への転換
- **仮説**: EXFIL 一本足 × fill × 少数精鋭テンプレで public を最大化。
- **結果**: 静的 N=300 で `local ≈ LB` を確立（exp003=27.0）。fill 転換で LB 2.5 倍（exp004=66.96）。
  **exp006 で 84.78 到達**。テンプレ過剰（exp007 / exp010）は退行。DEPUTY fill（exp008）で private 得点、
  ポートフォリオ（exp009=33.66）で 4 行得点。
- **学び**: **fill が最大のレバー**。テンプレは 5 が最適点。private は `email.send` の CONFUSED_DEPUTY のみ。

### Round 2（07-19, exp011–015）— exp006 周りの単一レバー A/B
- **結果**: public 系は**全て退行**（exp011=79.2 / exp012=73.4 / exp013=70.2 / exp015=75.8）。
  exp014=19.44 は DEPUTY の cell 多様化で exp008 を超えた。
- **学び（決定的）**: **exp006 は調整済みの局所最適**。単一レバーをどちらへ動かしても退行する。
  「トークン削減 → 候補増 → LB 増」は live で成立しない（発火率とのトレードオフ）。

### Round 3（07-21, exp016–020）— 未検証レバー + 密度ラダー移植
- **結果**: exp016=68.9（wrap-up 削減で大退行）/ exp017=VOID（harmony 注入のズレ）/
  exp018=84.96（cap 0.995・唯一「触っても下がらない」）。密度ラダー exp019=82.5 / exp020=81.5。
- **学び**: 局所最適は破れず。攻めた collapse は INVALID を招く。密度ラダーは別エンジンでも 84.8 帯を越えない。

### 移植バッチ（07-22, exp021–025）— canqiang / tetsutani の忠実移植
- **結果**: exp023=88.56（canqiang + cap 0.99）/ exp022=85.9 / exp021・024・025=VOID。
- **学び**: canqiang 移植が exp006 帯を上回り Round4 への布石に。
  **`REPLAY_BUDGET_MULT > 1`（リプレイ壁が予算より広い）への賭けは VOID**＝壁に余裕は無い。

### Round 4（07-24, exp026–030）— 抜本転換 ★plateau 突破
| exp | レバー | LB | 判定 |
|---|---|---:|---|
| **exp028** | **純 throughput 単発**（実測選択 + cap 0.995） | **90.99** | ★**新 champion・初の 90 超え** |

- **学び（決定的）**: **plateau(84.8) は「純 throughput」で破れた**。密度は live で単発に劣後
  （部分発火で N_eff が縮む）。continuation は無効を再確定。統合はアーム増で退行。

### Round 5（07-26, exp031–035）— 抜本レバーで 100+ 挑戦 + private ヘッジ

### Round 6（07-27, exp036–040）— deep-forge（reasoning-effort）× best-of
- **結果**: exp039=89.6（**exp028 と同一コードなのに −1.4**）/ exp037=88.1 / exp038=87.9 /
  **exp036=87.5（本命 deep-forge が最下位）** / exp040=20.8（private ヘッジ）。
- **学び（決定的）**: **reasoning-effort は system で設定され user 注入では上書き不能＝構造的に到達不能**。
  **同一コードで ±1.4 の分散が実在** → best-of が唯一の確実なレバー。

### Round 7（07-28, exp041–045）— 予算回収ノブの sweep

- **学び**: ノブの効きは分散に埋もれ、**単発 A/B では判定不能**。

### Round 8（07-29, exp046–050）— 研究開示レバーで探索（設計のみ・未提出）

  「gen2 の CoT に forge 注入経路は無い」を確定。新レバーは枯れた。

### Round 10（08-01, exp056–060）— ★VOID = 時間切れ確定
- **結果**: **全 5 件が VOID（0/5 全滅）**。完了 386〜758 分（成功例 1508 分より短い＝途中終了）。
  切り分けで提出物は正しく、失敗は live リラン側と確定。
- **学び（★最重要）**: **VOID / 空欄 / incorrect-format はすべて時間切れ**（ユーザ確定）。

### Round 11（08-01, exp061–065）— cap 保守化 ★VOID ゼロ
- **結果**: **5/5 全完走**。exp062=89.370（best）/ exp061=87.075 / exp063=86.940 /
  exp064=86.940 / exp065=86.310。
- **当時の結論**: 「cap 0.98–0.99 = 完走圏、0.995–0.997 = VOID 境界」
  → **この結論は Round13 で否定された**（下記）。

### Round 12（08-03, exp066–070）— public 100+ 奪回（frontier 移植）
- **前提の転換**: LB 直接確認で、上位 100–112 は現行 v3.1.2 の実スコア（全て 08-01/02 提出・
  凍結ゾンビではない）と判明。「public 飽和」の旧結論は撤回。
- **結果**: exp068=88.380（best）/ exp069=87.495 / exp066=**35.855**（terse で大退行）/
  exp067=VOID（安全既定なのに）/ exp070=VOID。
- **学び（決定的）**:
  1. **frontier 公開カーネルの移植では 100+ は再現できない**（~87–88 帯止まり）。
  2. **VOID は cap でなく draw の分散が支配** — 安全アンカー exp067 が VOID し、
     より攻めた exp068 が完走した。
  3. **terse 出力抑制は失敗**（発火率が崩壊）。**verbose 維持が正しい**。
  4. **forge-multipost は単発を超えない**。

### Round 13（exp071–075）— cap リスク曲線に散らす best-of
- **設計**: champion エンジンを 1 バイトも触らず、cap を 0.985 / 0.99 / 0.993 / 0.995 に散らす。
- **結果**: **2/5 完走**。exp073（cap 0.993）=**89.820**（Round13 best）/ exp072（0.995）=77.895 /
  **exp071（0.995）・exp074（0.99）・exp075（0.985）が VOID**。
- **学び（★Round11 の結論を否定）**: **最保守の cap 0.985 でも VOID し、
  より攻めた cap 0.993 が完走した**。「cap 0.98–0.99 は完走圏」は保証ではない。
  同一構成 `(0.99, probe2)` が exp062=89.370 / exp074=VOID と割れた。

### Round 14（08-09, exp076–080）— v15 取り込み + champion best-of
- **結果**: **5/5 完走**。exp076（0.995/probe4）=88.155（best）/ exp079（0.99/probe2）=88.065 /
  exp078（v15 cap 0.99）=87.750 / exp077（v15 cap 0.98）=86.895 / exp080（0.993/probe2）=86.805。
- **学び**:
  - **同一 cap 0.993 でも 89.820 ↔ 86.805 と −3.0 散る**（exp073 vs exp080）。
  - **同一構成 `(0.99, probe2)` は 89.370 / 88.065 / VOID に散る**（exp062 / exp079 / exp074）。
  - **v15 エンジンでは cap 0.98→0.99 が +0.855 と素直に効いた**（exp077 → exp078）。
  - 3 系統目の独立エンジン移植も champion 帯に届かず。
