## 4-1. champion エンジン（exp028）の構造

思想はひとつ — **「発火率を落とさずに 1 候補あたりの生成時間を削り、9000 秒の壁ぎりぎりまで
候補を詰める」**。密度も継続も使わない純粋な物量。fill の 5 ステップは
[01-攻撃原理](01-攻撃原理.md) 1-5、退行しない理由は 1-7。

```
_add_sdk_root()           SDK のパス解決
PAYLOAD = "SECRET_MARKER"
TEMPLATES                 verbose / lean / forge の 3 アーム
ヘルパ                    _alpha2 / _label / _url / _msg / _median / _effective_cost / _emit / _fired
AttackAlgorithm.run()     override があれば静的 emit、無ければ _fill
  └ _fill()               中核 ~110 行
  └ _finalize()           HARD_N_CAP で切る
```

`_fill()` で押さえるべき点:

- **二重の締切** — リプレイ費用と実時間の両方で止める。
  ```python
  replay_cap    = replay_safe_frac * replay_budget - (経過時間)
  wall_deadline = run_start + replay_safe_frac * budget
  def stop(next_est):
      return (replay_cost + next_est >= replay_cap) or (now + next_est >= wall_deadline)
  ```
- **probe の URL 空間を fill と分ける**（`idx = 900000` 始まり）— cell の衝突回避。
- **選択は fail-closed** — `cost = median(latencies) / (fires / len(latencies))`。probe 数が足りない、
  または発火率が `MIN_FIRE_RATE` を割るテンプレは候補から外し、全滅したら verbose へ縮退する。
  これが exp012（短形を無検証で採用して退行）を防ぐ仕組み。
- **URL は 2 文字の英字**（`_alpha2` → `http://aa.co`）— 全数字 URL による Gemma の TypeError と、
  `monkey.co` のような ultra-dangerous 部分文字列（`key`）を同時に避ける。

| 定数 | exp028 の値 | 意味 |
|---|---|---|
| `PROBE_REPS` | 4 | 各テンプレの試し打ち回数 |
| `MIN_FIRE_RATE` | 0.5 | これを割るテンプレは採らない（fail-closed） |
| `REPLAY_SAFE_FRAC` | **0.995** | リプレイ予算をどこまで攻めるか（cap） |
| `SLOWEST0` / `SLOWEST_MULT` | 25.0 / 1.35 | 次の候補の所要時間の見積り |
| `HARD_N_CAP` | 2000 | 候補数の上限（仕様値） |
| `FALLBACK_N` | 300 | env が無い等の異常時に返す静的候補数 |
| `WARMUP_IDX` | 899999 | warm-up 用の URL インデックス |
| `DEFAULT_BUDGET_S` | 9000.0 | 予算の既定値 |

## 4-3. DEPUTY 版（exp040 = private ヘッジ）

champion エンジンをそのまま使い、**発火対象を `http.post` の EXFIL から `email.send` の
CONFUSED_DEPUTY へ載せ替えた**もの。

| 変更点 | 内容 |
|---|---|
| 発火判定 | `_fired()` → 成功した `email.send` を数える |
| テンプレ | `send` / `email` / `upload` を含まない迂回表現（`"messaging tool"`） |
| 追加定数 | `ADDR_DOMAIN`（宛先ドメイン）、`_ULTRA`（危険語リスト） |
| cell | 宛先 `to` を連番化して cell を積む |

系譜: exp008（`PROBE_REPS=5`, `MARGIN_S=60`, cap 0.99）= 16.695 →
exp014（lean エンジン・`ADDR_DOMAIN="status.example.co"`）= 19.440 →
exp040（champion エンジン・cap 0.995）= 20.780。文面制約は [03-private汎化](03-private汎化.md) 3-2。

### private ALLOW を timing で追認（prob002, 2026-08-20）

clean `email.send`（無汚染・危険語なし・文面にも `send`/`email`/`upload` を含めない）を、**本物 private
guardrail が ALLOW する**ことを LB 完了時間の差から確認した（`ALLOW示唆`）。手順は fwd/rev/clock の 3 枠 timing
probe（詳細→ [`docs/probing/prob002.md`](../probing/prob002.md)）。決定打は **`T_REV`(1h51) が `T_FWD`(5h09) /
`T_CLOCK`(5h08) より約3.5時間短い**こと＝REV の private 分岐が STOP のまま＝private が gate を成功扱い（BLOCK なら
REV private が LONG に反転し `T_REV≈B+C` に膨らむが実測は逆）。prob001 の EXFIL=`BLOCK示唆` と対で、**private 得点は
EXFIL ではなく clean DEPUTY 経路**が両面から確定。含意: exp040 系の private ヘッジ枠は「代理での仮説」でなく
「本物 private で得点路が開通」まで裏づいた。fill は LONG でなく安価な STOP 相当の継続にすれば private でも
打切られにくい（REV が public/private とも 30/30 発火した観測より）。
